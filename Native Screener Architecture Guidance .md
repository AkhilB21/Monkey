2. The normalization layer is the heart — build it as one cached module. Create nse_engine/features.py that takes one symbol's daily OHLCV and returns a per-bar feature frame. Every feature is rolling-window percentile/z-score ending at the current bar — this is critical: an expanding/centered window leaks the future into "today's" score. Cache these frames per symbol (parquet) during sync, so a full-universe scan is a fast read, not 2400 indicator recomputes. That's what makes "runs in seconds" actually true.

3. Follow the roadmap order, but instrument it. Step 1 (empirical discovery) is correctly first. Make the success definition crisp (the 15%/20d / <8% DD example is good), then profile winners vs non-winners with effect sizes (Cohen's d / Mann-Whitney U), and derive weights proportionally. Use a strict time-split: train on 2024–2025, validate on 2026. Don't tune on the same window you profiled.

4. Validate the "emergent phase" claim early. The doc's key bet is that normalized features separate into 4 phases without explicit classification. That's plausible but unproven. After Step 2, run a quick scatter/cluster check — if Recovery and Bottoming Out don't separate cleanly on the features alone, you'll need a small arbitration rule (e.g., "MA structure intact" as a Recovery qualifier). Better to discover that in Step 2 than at integration time.
Ways to make it better

1. Add a cross-sectional layer (the biggest upgrade). The doc normalizes each stock against its own history. Add a per-day ranking across all 2400 stocks (e.g., "RSI is in today's top decile universe-wide"). Cross-sectional ranks auto-adapt to market regime — when the whole market is oversold, per-stock RSI percentiles all read "low," but cross-sectional ranking still surfaces the strongest. Two complementary views, both cheap.

2. Regime overlay, smoothed. Instead of binary "NIFTY above/below 50-DMA," use the index's own z-score/percentile. Binary switches at the boundary cause exactly the discontinuity the doc dislikes in buckets. Pull NIFTY via yfinance (^NSEI) into the repo like any symbol.

3. VIX-free volatility overlay. India VIX is hard to source reliably; use cross-sectional median ATR percentile as the volatility-regime signal. Zero new dependencies, same effect.

4. Rank cutoffs, not threshold cutoffs. When the whole market bounces, threshold-based scoring floods the Recovery table. Output the top-N Recovery and top-N Momentum by score per day (or require both score-threshold and cross-sectional percentile). The tables stay curated at any market state.

5. Add price-volume divergence (PVD) as a headline feature. You already compute VPT in indicators.py; a 5/10-bar price-vs-volume slope divergence is a strong, cheap momentum-quality signal the Chartink pipeline could never produce — good marketing for the native screener's upgrade.

6. Keep a parallel-run safety net. Don't delete chartink_pipeline/ until the native screener has produced byte-compatible CSVs for 2 weeks in parallel and the Recovery tables match on overlapping symbols. This de-risks the Playwright removal (Step 9).

7. Natural later upgrade: once the normalized feature frame exists, it's a clean input to a lightweight interpretable model (logistic/GBM) for ranking — keep the explicit score for transparency, use the model only to re-rank within the top-N. This is optional and not needed for v1.

Bottom line: the architecture is right — the two-layer design (normalized features + regime overlays) is genuinely better than per-bucket scoring. Implement it in the roadmap's order, cache the feature frames, validate the phase separation empirically before committing to "emergent only," and add the cross-sectional layer — that's the single highest-value improvement.
